# Team HQ и мастерская: источники и проверка точности

Обновлено 2026-11-13. Реализация читает ассеты установленной игры во время
запуска. Извлечённый машинный код не включается в бинарник; дизассемблирование
использовалось для проверки трактовки форматов и параметров.

## Экраны и данные

- `UI/teamhq/select_team.gib`, `teamhq.gib`, `hq_robots.gib`, `editteam.gib`,
  `bot_cell.gib`, `nobot_cell.gib`, `team_cell.gib` задают композицию и кнопки.
- `hq_league.gib`, `league_cell.gib`, `hq_events.gib`, `eventcell.gib`,
  `joinevent.gib`, `hq_history.gib` задают вкладки и окно выбранного события.
- Шрифты GIFF, картинки, выделение/наведение и обрамления читаются из штатных
  файлов. Тонкие границы растеризуются по центрам пикселей, включая дробные
  координаты из GIB. Панель инвентаря растягивает сетку до двух столбцов и трёх
  строк, в исходном порядке слотов: 0/3, 1/4, 2/5.
- `Teams/Teams.txt`: список активных команд и 16 записей переменной длины.
  Парсер сохраняет неизвестные строки и исходные переводы строк; правки имени,
  девиза, логотипа и списка слотов не пересобирают сезонные данные.
- BOT хранятся в `Teams/TeamN/BotN.bot`. Save/Import обновляют список слотов;
  при ошибке записи команды восстанавливается прежний BOT. Scrap и Delete
  убирают ссылки из штатного списка; оставшиеся файлы не отображаются и могут
  быть перезаписаны при повторном использовании слота.
- `AI/Teams.txt`: 15 соперников; `Events.txt`: 25 записей с явным ID и числом
  раундов. Сохранённые индексы расписания используются непосредственно.

## Проверка по оригинальному EXE 1.12

Адреса относятся к имеющемуся оригинальному бинарнику, а не к нашему движку.

| Адрес | Наблюдение | Применение |
|---|---|---|
| `0x004fabf0` | Загрузчик записей команд: статистика, переменный список призов, расписание, завершающие очки/убийства/класс лиги | Чтение истории и лиги, сохранение неизвестных полей без изменений |
| `0x00500398`, `0x0050040c` | Очки игрока и очки каждого соперника берутся из состояния выбранной команды | Таблица лиги не подменяет результаты статическими AI-сохранениями |
| `0x0050051b` | Место вычисляется после сортировки таблицы | Стабильная сортировка по очкам и нумерация мест |
| `0x0044fbc9` | Загрузка `UI/botlab/baseplate_grid.bmp`, множитель цвета 0.5 | Исходная зелёная текстура основания в Components/Wiring |
| `0x0044fcac`, константа `0x006a69fc` | Координаты UV основания равны x/z, умноженным на 8 | Масштаб квадратной разметки без новой текстуры |
| `0x0047840a` | Загрузка `Point Selection.tga` | Исходный маркер перетаскиваемой точки |
| `0x00478fdf`, `0x0047905d` | Вызов `sounds/point_plotted.wav` | Исходный звуковой сигнал при построении контура |

`blueprint.bmp` не содержит точечной сетки: она добавляется при отрисовке.
В нашем редакторе шаг видимой сетки совпадает с шагом привязки. Выбранное
крепление рисуется исходной моделью `AP_box_selected.gmf`; преобразование
совпадает с используемым при выборе мышью. Предпросмотр размещаемой детали
рисуется дополнительным проходом поверх глубины основной сцены и окрашивается
в красный при отказе проверки установки.

Звуки компонентов выбираются по `attachsound` из действующего определения,
с учётом локальных переопределений каталога. PCM WAV декодируются один раз;
количество одновременно воспроизводимых сигналов ограничено.

## Воспроизводимые проверки

### Указатели выбранного контрола Wiring

В оригинальном EXE обработчик `0x443cb0` очищает указатели и собирает список
компонентов выбранного контрола через `0x4db810`; несколько назначений одного
компонента дают один указатель. `0x4440d0` создаёт синий ствол от Control Board,
`0x443fc0` — зелёные четырёхточечные ветви к деталям. Высоты 1,6 и 1,0 берутся
из `0x6a6268`/`0x6a626c`, толщина 4 — из `0x6a6270`. Порядок RGB проверен по
конструктору цвета `0x61b5c0` и упаковке каналов в `0x5b48c0`.

Наши маршруты строятся по координатам контрола в BOT и позированной геометрии
общего сборщика. Центр и радиус видимой геометрии служат якорями: скрытые физические
прокси не смещают указатели. Они отображаются поверх модели отдельным слоем,
не участвуют в выборе деталей или физике и не попадают в Test Robot.
Две сетки переиспользуются; вершины обновляются при смене камеры/выбора/документа.
Чтение маршрутов не меняет BOT. При отсутствии платы указателей нет.

`--workshop-check` проверяет выбор Forward/Fire/пустой ячейки, вращение модели,
снятие назначения через диалог, Undo, Delete Control, сохранение/повторную загрузку
и уход с Wiring. Снимки `logs/hq-wiring-*-pointers.png`,
журнал `logs/wiring-pointers-offscreen.log`.

```bash
cargo test --workspace --offline --locked
cargo test -p ra2-rs original_ --offline --locked -- --ignored --nocapture
cargo clippy -p ra2-rs --all-targets --offline --locked -- -D warnings
```

Нативные тесты требуют установленную рядом игру. Тест управления данными
работает во временной папке и проверяет неизменность исходного Teams.txt.

`--workshop-check --menu --objects 0 --game-dir PATH` запускает настоящую
композицию и обработку мыши без оконного сервера, рендерит экран в текстуру
и пишет `logs/hq-*.png`. Перед этим нужно создать `logs/`, передать копию
`Teams/` и `Robot Designs/` и выбрать доступное Vulkan/аудиоустройство;
для автоматической проверки подходят llvmpipe и null ALSA. Разрешение
настройки проверки — 800×600. Проверка охватывает навигацию, свободный вогнутый
контур, недопустимое/допустимое размещение, установку и отмену Save Prompt.

Дополнительно проверено сохранение нового пустого корпуса. В BOT-парсере
индексы вершин деформации и ID креплений теперь читаются как индексы, а не
количества элементов: прежняя проверка отклоняла корректный корпус без деталей
из-за малого остатка данных после последнего индекса. Новый тест также проверяет,
что экспорт не помечает слот команды сохранённым, а импорт требует сохранения.

## Явные отличия

Пиксельная идентичность всех экранов не заявляется: освещение 3D, отдельные
допуски установки, курсоры, ввод текста и некоторые детали поведения GIB
реализованы самостоятельно. Строгое совпадение алгоритмов покраски/UV и Havok
не достигнуто. Options остаётся панелью настроек нашего движка.

Сезонные бои и генерация нового сезона ещё не перенесены. Вкладки штаба читают
сохранённые данные, но не симулируют турнир. При отсутствии расписания показаны
первые девять штатных событий, без записи нового сезона; Enter Event сообщает
о недоступности соревнований. Неподдержанная функция не изменяет прогресс команды.

Дальнейшие ограничения мастерской и предыдущие проверки описаны в
[EDITOR_COMPATIBILITY.md](EDITOR_COMPATIBILITY.md).
