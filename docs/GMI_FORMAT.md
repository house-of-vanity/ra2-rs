# Поддержка GMI v3

Декодер написан на Rust. Для исследования структуры использованы материалы
проекта Martijn Pieters: [PyRA2 0.1.1](https://sourceforge.net/projects/pyra2/files/PyRA2/PyRA2-0.1.1/),
в частности `docs/GMF file format analysis.txt`, `GMIModel/Import.py` и материалы
его тестов. PyRA2 распространяется под LGPL-2.1-or-later; его Python-код не
включён в workspace и не используется при запуске. Геометрия дополнительно
проверена по текстовым экспортам из локальной игры.

Архив исследования: `PyRA2-0.1.1.tar.gz`, SHA-256
`238f87c3af35c250b3284f2fbb6a61ffcd28bc96e5234403a777e56be5b6f12f`.

## Структура

Заголовок: `GMI`, затем little-endian `u32`: версия 3, тип модели 1, два служебных
значения. Итого 19 байт. Затем записи с заголовком `(id, flags, payload_length)`:
три little-endian `u32`. Строки: длина `u32` и байты с завершающим нулём.
Числа геометрии: little-endian `f32`; индексы и счётчики: `u32`.

| Записи | Обработка |
|---|---|
| 1, 18 | Сцена, список объектов |
| 7, 8 | Материалы и вложенные материалы |
| 14, 15 | Текстуры, параметры UV и номера каналов |
| 2, 16, 17 | Объекты, сетки, матрицы |
| 21 | Точки крепления / пользовательские свойства |
| 31, 32, 33 | Дерево физических тел и их свойства |
| 4, 5, 30, 42, 49, 51 | Известная схема читается; исходные байты сохраняются в `ImportReport::extensions` |

Последняя группа включает старые камеры/свет, параметры симуляции, соединения,
демпферы и отключённые пары столкновений. Применение этих данных в runtime ещё
не реализовано. Неизвестный тип записи вызывает ошибку с байтовым смещением.

## Особенности совместимости

- У исходного экспортёра неверны длины некоторых контейнеров, сеток и физических
  записей. Декодер читает известную схему и проверяет фактически доступные байты,
  не перемещает курсор по неверной длине. Расхождения попадают в отчёт.
- В некоторых UV-тройках неиспользуемая W-координата содержит `0xffffffff` (NaN).
  Она не нужна для двумерной текстуры. Нечисловые U/V в отдельных призовых моделях
  заменяются нулём с явной диагностикой. Нечисловые позиции геометрии отвергаются.
- Некоторые модели ссылаются на несуществующий подматериал. Это отмечается в
  отчёте; renderer использует первый доступный подматериал как приближение.
- Число элементов, вложенность, арифметика размеров и границы буферов проверяются.
  Для бинарного файла установлен лимит 64 MiB; для счётчиков — 2 000 000 элементов;
  для рекурсивных материалов/тел — глубина 64.
- Служебные коллизионные и отображаемые прокси не взаимозаменяются по догадке:
  исходные ссылки и типы геометрии сохраняются для следующего этапа физики.

Renderer использует диффузные карты и подходящий UV-канал. Если диффузная карта
и карта непрозрачности ссылаются на одну RGBA-текстуру с одинаковыми UV, используется
настоящая альфа-маска с отсечением пикселей и записью глубины. Так отображаются
отверстия Square Extender: металл непрозрачен, отверстия прозрачны. Для отдельных
карт непрозрачности пока остаётся приближение общим alpha; старые световые карты
не воспроизводятся.
Вершинные цвета и прочие карты, кроме диффузной/непрозрачности, читаются для
корректного прохода файла, но ещё не передаются в отображение. Текущий декодер
поддерживает базовые модели GMI v3; другие версии и типы не объявлены совместимыми.
